# 番剧追踪（单人版）UI/UX 改版建议

## 页面结构

1. **顶部摘要卡**：标题「番剧追踪」，副标题「本周继续看下去」，右侧显示 `已看 / 总数`；下面用细进度条表现完成比例。空清单时摘要卡仍保留，但显示「从搜索一部番开始」。
2. **主操作**：摘要卡下方放一枚整行搜索入口（带放大镜、占位「搜索番剧名称」），点击后进入现有 `anime-search` 的 `pick` 模式；保留一个小的「手动添加」文字入口作为离线兜底。这样默认路径有封面、集数、放送状态等真实信息，不把用户挡在手填表单里。
3. **筛选条**：`全部`、`追更中`、`已看完` 三个等宽 tab，右侧为排序按钮（最近添加、更新时间、标题）。筛选切换不改变数据，只改变当前列表。
4. **番剧卡片**：横向卡片（封面 72×96rpx + 内容 + 进度操作）。内容顺序为番名（最多两行）、`连载中/已完结` 标签、`第 X / Y 集` 和「更新：周X」；右侧显示圆形进度按钮。点击卡片进入轻量详情/进度 sheet，点击圆形按钮直接 `+1`，避免误触整卡。
5. **已看完**：默认折叠为一行「已看完 · N 部」，点击展开；卡片降低对比度但保留封面色彩，避免大面积灰字和删除线造成不可读。

## 关键交互状态

- 首次进入：摘要卡 + 搜索入口 + 示例空态插画/文案；不要直接渲染 t-empty 后留下大片空白。
- 搜索中：搜索页保持搜索词，结果区显示 2–3 个骨架卡；网络失败显示「重试」按钮并保留关键词。
- 加入成功：卡片从列表顶部淡入，摘要计数同步变化；Toast 仅作辅助反馈。
- 封面失败/无封面：统一使用首字色块（与共享板 `coverFallback` 视觉一致），同时保留文本信息。
- 更新状态未知：标签使用中性灰「状态未知」，不要把缺失数据当作「已完结」。
- 进度边界：总集数已知时禁止超过总集数，显示「已追平」；总集数未知时显示 `第 X 集`，允许继续递增。
- 删除：左滑操作区同时提供「删除」，并支持撤销 snackbar，减少误删依赖确认弹窗。
- 编辑模式：把排序改为长按拖拽（若暂不支持拖拽，至少在编辑态显示明确的拖动把手和「完成」按钮）；普通浏览态隐藏上下箭头，降低视觉噪声。

## 视觉层次与可用性

- 页面背景沿用全局 `--td-bg-color-page`；摘要卡使用品牌浅色底，番剧卡维持白底，保证主次层级。
- 卡片内最小点击区域 88rpx；进度按钮提供 `aria-label="将番名标记为第 X 集"`，颜色只表达状态，文字同步表达状态。
- 番名使用 `-webkit-line-clamp: 2`；集数和放送状态使用不换行标签，避免长标题挤压操作按钮。
- 动效只保留 180–300ms 的淡入、勾选缩放；尊重 `prefers-reduced-motion`，不要使用当前 360° 旋转和跨分组飞行动画，减少晕动并避免列表重排跳动。
- 深色模式下封面、标签、进度条都从 TDesign 变量取色；不要写死白底/浅灰文字。

## 数据模型迁移提示

现有 `anime_checklist_data` 是 `{ id, name, watched, createTime }`。加入真实番剧后建议扩展为：

```js
{
  id, sourceId, name, cover, totalEp, airStatus, airDay,
  currentEp: 0, watched: false, createTime, updatedAt
}
```

读取旧数据时保留 `name`，给缺失字段填安全默认值；列表排序依据 `updatedAt || createTime`。搜索页回带 `sourceId/name/cover/totalEp` 后再拉详情补齐 `airStatus/airDay`，失败也应先落库搜索结果并显示「状态未知」。
